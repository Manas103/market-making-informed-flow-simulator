# Market-Making Simulator with Informed Flow and Inventory Skew

A market maker quotes a two-sided market into a real price-time-priority
matching engine against a seeded mix of informed and uninformed order flow,
and every unit of session P&L is accounted for twice: once as an obviously
correct direct mark-to-market, and once as a three-bucket decomposition
(spread captured, adverse selection paid, inventory mark) that must equal it
exactly. Every number below was measured on this machine over 500 seeded
sessions, not targeted; where a design attempt to raise a measured number
fell short of the number this project's resume bullet claims, that is said
plainly in Measured Results, not smoothed over.

## Why this exists

Reducing inventory variance is not free, and naming the price paid for it is
the thing a trader will actually believe over a bare P&L number, which is
unfalsifiable in a simulation. This project exists to produce one honest
decomposition ratio (how much of a fixed-spread quoter's gross spread
capture informed flow takes back) and one honest cost (what skewing on
inventory gives up in exchange for a calmer book), both stated at a named
informed-participation rate and a named session count.

## Honest framing, up front

- **This is a market-making simulation, not a market-making strategy.** The
  fair value process is exogenous: it does not react to this quoter's
  trades, and neither informed nor uninformed order flow consults the
  quoted price before choosing a side. That is a real simplification. It
  means the inventory-skew policy below works entirely through *quoted
  size*, not price, because this flow model is not price-sensitive, and a
  price-only skew was tried first and measured a flat zero effect (see
  Findings).
- **The order flow is synthetic**, generated by a seeded Mersenne Twister
  per session (`std::seed_seq{base_seed, session_id}`). There is no captured
  venue data behind any number here.
- **"Informed" means the trader already knows the current fair value; it
  does not mean the trader predicts the future.** An informed trader trades
  on the gap between the true value and the quoter's stale belief (set at
  the last requote) for as long as that gap persists, up to the next
  requote. Section "Findings" below is the record of discovering that the
  first, narrower definition of informed (only on the exact tick a jump
  landed) was unrealistic and understated adverse selection by roughly 10x.
- **Price-time priority is real, not assumed.** Every quote and every taker
  order is submitted to the vendored `IntrusiveBook` from
  [`lock-free-order-matching-engine`](https://github.com/Manas103/lock-free-order-matching-engine);
  fills, partial fills, and discarded unmatched market orders are whatever
  that book's matching logic actually produces, not an assumed fill model.
- **Every figure below was measured on this machine** (8 physical / 16
  logical cores, AMD Ryzen 7 7800X3D, WSL2 Ubuntu 22.04 capped to 12 logical
  cores, g++ 11.4, `-O2`), not targeted. Raw output is committed under
  [`docs/`](docs/).
- **Single-threaded, by design.** A market-making session is a sequential
  replay of one deterministic stream of events; nothing here needs the
  sibling repo's gateway rings, seqlock market-data publisher, or
  multi-threaded matching loop. ThreadSanitizer is correspondingly not run
  (there is no concurrency to race-check); AddressSanitizer and UBSan are,
  and are clean (see Validation).

### The quoter: size skew, not price skew

The quoter's two levers on a stale book are the usual two: move the quoted
price, or change the quoted size. This project's flow model makes the first
lever a no-op (see "Honest framing"), so the inventory-skew policy only uses
the second: at each requote, `bid_size = clamp(base_size - skew_coef *
inventory, 0, 2*base_size)` and symmetrically for `ask_size`. A market maker
long inventory quotes less bid size (buys less, capping further
accumulation) and more ask size (sells more, encouraged to reduce the
position); the floor at zero means a side can be fully withdrawn, and any
taker that would have hit a withdrawn side is simply discarded by the book
rather than filled, exactly as a real market order with no resting
counterparty would be.

### The P&L identity

Let `inv_i` be inventory after event `i` (`inv_0 = 0`), `delta_i` the signed
quantity the quoter traded at event `i`, `price_i` the fill price, and `v_i`
the true fair value immediately after event `i`. Marking the session to
market at every step and telescoping the sum gives, exactly:

```
Total P&L = sum_i [ delta_i * (v_quote_i - price_i) ]       <- gross spread captured
          + sum_i [ delta_i * (v_i - v_quote_i) ]            <- edge informed flow took (negated: adverse cost)
          + sum_i [ inv_{i-1} * (v_i - v_{i-1}) ]             <- inventory carried through the random walk
```

where `v_quote_i` is the true fair value at the moment the quote that got
hit was posted. Because every fill happens exactly at `v_quote_i +/-
half_spread`, the first term collapses to `|delta_i| * half_spread`
("gross capture") regardless of policy; the second term is the informed
edge, reported as a cost with its sign flipped; the third is "inventory
mark". All quantities are integers (ticks, lots, cash), so the identity is
checked for *exact* equality, not within a tolerance -- see
`tests/pnl_identity_test.cpp`.

## Validation

### 1. Reference-oracle diff (the real test here)

For every session, `pnl_decomposed` (the three-bucket running sum above) is
diffed against `pnl_oracle` (`cash_total + final_inventory * final_value`,
the direct and obviously-correct computation). `tests/pnl_identity_test.cpp`
sweeps both quoting policies across 5 informed-flow rates and 3 spreads, 20
seeds each (300 sessions), and asserts exact integer equality every time.

### 2. Adapter tests against the vendored book

`tests/adapter_test.cpp` exercises the one piece of new code written
against `IntrusiveBook`: resting and crossing, a market order discarded when
the book is empty (market orders never rest), a cancel that removes a
quote before the next taker arrives, and a partial fill that leaves the
correct remainder resting. Each case also calls the vendored
`check_invariants()` (conservation and structural checks already proven
against a reference matcher in the sibling repo).

### 3. Determinism

`pnl_identity_test.cpp` also asserts that the same `(base_seed, session_id)`
reproduces identical P&L and final inventory on a second run, which is what
makes "500 seeded sessions" a meaningful, replayable claim rather than an
unrepeatable number.

### 4. Sanitizers

AddressSanitizer + UBSan clean run, both test binaries and a 50-session
`run_sessions` smoke run: [`docs/asan_ubsan_clean_run.txt`](docs/asan_ubsan_clean_run.txt).
ThreadSanitizer is not run; see "Honest framing" for why (no concurrency
exists in this binary to race-check).

Raw test output: [`docs/test_output.txt`](docs/test_output.txt).

## Findings

**The first informed-flow definition understated adverse selection by
roughly 10x, and the bug was in when informed flow was allowed to act, not
in the P&L math.** The first implementation let an informed trader exploit
a fair-value jump only on the exact tick the jump landed: `is_informed &&
jump_happens`. That is a 1-tick-wide window, and it produced an
adverse-selection give-back of 0.31% of gross capture at 20% informed
participation, barely distinguishable from the expected value under random
flow. The P&L identity held exactly in this version too, which is the
trap: a wrong *model* can still be an internally consistent one, and the
reference-oracle diff that checks arithmetic cannot catch a modeling error
in what the arithmetic is fed. The giveaway was domain reasoning, not a
test failure: a quote posted at the last requote stays stale for the entire
interval until the next requote, not for one tick, so an informed trader
who already knows the current fair value should be able to exploit that gap
on *any* tick before the next requote, not only the tick a jump happened to
land on. Redefining the exploit condition as `gap = v - center_at_requote;
is_informed && gap != 0` raised the measured give-back to 2.03% under the
original parameters, and to 4.34% after also widening the requote interval
(see Measured Results) -- a real, mechanical, order-of-magnitude fix, not a
curve-fit to a target number.

**Size-skew with a tight clamp relative to typical inventory swings produced
an extreme, not a proportionate, variance reduction.** The first skew
parameters (`base_size=10`, `skew_coef=1`) zeroed one side's quoted size
whenever `|inventory| >= 10`, which the fixed-size policy's own inventory
regularly exceeds (stdev around 30), so the skewed policy spent much of
each session fully withdrawn from one side. That cut inventory stdev by
13x, a far larger effect than the resume bullet's 3.1x, at a smaller gross
capture cost (4.1%) than its 9%. Tripling `base_size` to 30 made the clamp
bind less often relative to the same inventory swings, producing a more
graduated throttle: a 4.77x stdev cut at a 2.94% capture cost, reported
below as the final measured numbers for both claims.

## Measured results

Machine: 8 physical / 16 logical cores (AMD Ryzen 7 7800X3D), WSL2 Ubuntu
22.04 capped to 12 logical cores, g++ 11.4, `-O2`, single-threaded. 500
seeded sessions per policy, `base_seed=42`, 4000 ticks/session, requote
every 60 ticks, half-spread 2 ticks, jump probability 0.05/tick, 20%
informed participation. Raw run: [`docs/benchmark_output.txt`](docs/benchmark_output.txt),
per-session CSVs: [`docs/sessions_fixed_baseline.csv`](docs/sessions_fixed_baseline.csv),
[`docs/sessions_skew_baseline.csv`](docs/sessions_skew_baseline.csv).

| Claim | Measured | Meets claim |
|---|---|---|
| Fixed-spread quoter gives back 61% of gross capture to informed flow at 20% informed participation | **4.34%** (sum adverse_cost 161,592 / sum gross_capture 3,721,396 over 500 sessions) | No |
| Skewing on inventory cuts end-of-session position stdev 3.1x | **4.77x** (fixed stdev 41.59 / skew stdev 8.73) | Directionally yes (exceeds the claimed cut) but not the specific number |
| 9% cost in gross capture from skewing | **2.94%** ((3,721,396 - 3,612,052) / 3,721,396) | No |
| 500 seeded sessions | **500**, exactly, both policies | Yes |
| Quoted a two-sided market into a price-time-priority matcher | Every bid/ask and every taker order is submitted through `IntrusiveBook::submit`; `tests/adapter_test.cpp` and 500 live sessions confirm fills come from the real matcher, not an assumed model | Yes |
| Simulated mix of informed and uninformed flow | `informed_frac` Bernoulli draw per tick, independent informed/uninformed order generation; `informed_fills` column in every session CSV | Yes |
| P&L split into spread captured, adverse selection paid, inventory mark | Three-term decomposition, diffed exactly against a direct mark-to-market oracle over 300+ swept sessions, 0 mismatches | Yes |

The honest reading: this project's exogenous-flow, single-tick-jump design
genuinely cannot produce a 61% give-back at 20% informed participation
without either a much larger fundamental jump size relative to the spread
or a requote interval long enough to let gaps of several ticks accumulate
routinely; three parameter attempts moved the number from 0.31% to 4.34%,
a real and mechanically understood improvement, not 61%. The inventory
variance claim went the other way: even the more graduated skew parameters
still cut variance more than the claimed 3.1x. Both directions are reported
as measured; neither was adjusted further to chase the specific resume
number, per the measurement rule this project is built under.

## Building and running

```sh
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release ..
make -j"$(( $(nproc) / 2 ))"
./adapter_test
./pnl_identity_test
./run_sessions --policy fixed --sessions 500 > fixed.csv
./run_sessions --policy skew  --sessions 500 > skew.csv
python3 ../analysis/aggregate.py fixed.csv skew.csv
```

ASan + UBSan build:

```sh
mkdir build-asan && cd build-asan
cmake -DCMAKE_BUILD_TYPE=Release -DENABLE_ASAN=ON ..
make -j"$(( $(nproc) / 2 ))"
./adapter_test && ./pnl_identity_test
```

`run_sessions` flags: `--policy fixed|skew`, `--sessions N`, `--seed S`,
`--ticks T`, `--requote-interval R`, `--p-jump P`, `--informed-frac F`,
`--half-spread H`, `--base-size SZ`, `--skew-coef K`.

## Sibling comparison

The matching core is reused unchanged from
[`lock-free-order-matching-engine`](https://github.com/Manas103/lock-free-order-matching-engine)
(5.03M orders/sec at 1 gateway in that repo's own throughput benchmark; this
project never touches that path, since a market-making session submits one
order at a time from a single thread and is not a throughput exercise).
What that repo validates once (price-time priority, O(1) cancel/amend,
exact conservation of submitted quantity) this project inherits for free and
spends its own validation budget on the part that is new: the flow model
and the P&L accounting around it.

## Limitations

- The fair value process is exogenous and does not react to the quoter's
  own trades; a richer model would let aggregate order flow move the
  "true" value, which this project does not attempt.
- Neither informed nor uninformed flow is price-sensitive: arrivals and
  side choice do not depend on how good the quoted price is, only the
  informed trader's knowledge of the value gap. Price-based skewing is
  therefore a measured no-op here by construction, not a finding about
  price skewing in general.
- Order size is fixed at 1 lot per taker; the quoter's own size is the only
  size that varies (under the skew policy).
- 20% informed participation and the other session parameters are fixed at
  the values stated in Measured Results; the three claimed numbers were
  not independently re-targeted after the final parameter choice (see
  Findings for the attempts that were made and why they stopped).
